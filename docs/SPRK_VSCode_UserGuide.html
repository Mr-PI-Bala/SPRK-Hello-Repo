📖 Markdown Opens In Preview

SPRK repositories can include this custom setting to make reading documentation smooth right away:

{
  "workbench.editorAssociations": {
    "*.md": "vscode.markdown.preview.editor"
  },
  "markdown.preview.openMarkdownLinks": "inPreview"
}

That makes Markdown much easier for new coders to read first before diving into code changes!

✏️ Edit A Markdown File

If a Markdown file opens directly in preview mode and you want to jump in and code/edit:

  1. Right-click the file tab or file in the Explorer sidebar.
  2. Choose Open With...
  3. Choose Text Editor.

Pro-tip: Double-clicking the tab or file may also reopen it for editing depending on your current VS Code setup state.

💾 Save Your Work

Always remember your best friend when coding:

Ctrl+S

Or press Ctrl + S! Make sure to save your files before running checks, committing changes, or switching branches.

⌨️ Preview Shortcuts

Supercharge your workflow with these handy Markdown preview shortcuts:

  • Ctrl + Shift + V: Open Markdown Preview in a new tab.
  • Ctrl + K, then V: Open Preview right beside your editor side-by-side!

How to use Ctrl + K, then V (two-step shortcut):

  1. Hold down Ctrl and press K.
  2. Release both keys.
  3. Press V. Boom! Side-by-side preview activated! 🌟

📊 Mermaid Diagrams

SPRK uses awesome Mermaid diagrams right inside Markdown files to map out logic and flows.

Good news: You don't need a Mermaid account! GitHub renders Mermaid diagrams automatically, and Codespaces handles them smoothly with Markdown Preview and the recommended Mermaid extension.

🎨 Markdown Preview Theme

SPRK repositories include a clean stylesheet configuration for previews:

{
  "markdown.styles": [
    "docs/styles/markdown-preview.css"
  ]
}

That stylesheet keeps Markdown previews looking sharp and readable in dark mode across GitHub web, github.dev, Codespaces, and VS Code Desktop.

Note: If your preview looks stark white with low contrast, it means the preview webview isn't loading the expected dark styling properly.

📱 iPad Preview Troubleshooting

On iPads and tablets, github.dev and Codespaces run entirely inside the mobile browser, meaning the Markdown preview runs inside a browser webview. Sometimes the editor theme and the preview webview don't sync up instantly.

Try these quick steps if it acts up:

  1. Confirm your repository has .vscode/settings.json.
  2. Confirm .vscode/settings.json includes markdown.styles.
  3. Close the Markdown preview tab.
  4. Reopen your README.md file.
  5. Open the Command Palette (Ctrl+Shift+P or command menu).
  6. Run Developer: Reload Window.
  7. Reopen your Markdown Preview.
  8. If the preview stubbornly stays white, open the same README in normal GitHub web view instead of github.dev to inspect the rendered Mermaid diagram smoothly.

If a Chromebook preview works smoothly but an iPad preview stays white, treat it as an iPad browser webview quirk. Your repository files are completely safe—feel free to use standard GitHub README view for reading and Codespaces editor view for coding!
