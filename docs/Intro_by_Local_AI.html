🎓 SPRK Hello Repo

Welcome to Your Coding Mission Map

This is your guide to the **Hello Repository** — a collection of browser-based games where you'll learn programming concepts by playing, changing, and sharing. Grab your notebook and let's dive in!

🗂️ Repository Structure

This folder contains everything you need to play missions, run tests, and follow the learning path. Here's what each part does:

🎮 missions/

All playable games live here. Each mission has its own `server.py` (Python backend) and `src/app.js` (JavaScript logic). You'll edit the code to change game behavior.

🧪 tests/

All game validation lives here. Playwright runs headless browser tests to make sure your changes don't break the real backends or shared state.

📚 docs/

The single source of truth for guides, mission instructions, and classroom hosting tips. Every student should read this first!

⚙️ ops/README.md

Your personal hygiene checklist — branch rules, commit cleanup, and how to hand off your work cleanly.

🚀 How to Get Started (5 Steps)

  • 1. Clone the repo — Get your local copy from GitHub or the assigned URL.
  • 2. Read your mission's docs — Open `missions//docs/MISSION_GUIDE.md` to understand what you're building.
  • 3. Create a branch — Never commit directly to `main`. Use `` branches.
  • 4. Run the game locally — Open `src/app.js` in your browser or use `npm run start` if needed.
  • 5. Commit & push a PR — Make small changes, run tests with `npm test`, then submit.

    • 🧹 Ops Hygiene Checklist

    Keep your repo clean so everyone can follow along. Run these before you commit:

    • ✅ Only intended files changed (`git status --short`)
    • ✅ `node_modules/`, `.env`, Python caches, and browser artifacts are **NOT** committed
    • ✅ Tests pass with `npm test` before you push a PR
    • ✅ Your branch is named clearly (e.g. `fix-slow-timing`)
    • ✅ Write a short summary in your PR title and body

    💡 Pro Tip: If you get stuck on tests, remember — you can run the full test suite anytime with npm test. The Playwright harness spins up a real browser against the Python backend so you're testing real behavior.

    🛠️ Toolchain at a Glance

    All missions share these core tools so your codebase stays consistent:

    Python (Flask)

    All Python backends live in `server.py`. They handle shared state like leaderboards, timers, and multi-device game logic.

    JavaScript / TypeScript

    All frontend games use vanilla JS or TS. Shared utilities live in `_shared/sprk_app.js` and `_shared/sprk_mission.css`.

    Playwright

    All tests run headless browsers against the real Python backend — no fake mocks, just real behavior.

    🎯 Remember: Play, Change, Share. The best way to learn is by breaking things (safely) and fixing them together.

    Questions? Check out AGENTS.md, the mission's MISSION_GUIDE.md, or ask your facilitator.
